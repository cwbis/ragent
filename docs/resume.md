## 项目经验

### Ragent — 企业级 RAG 智能体平台

| | |
|---|---|
| **类型** | 个人 / 团队项目 |
| **时间** | [开始时间] — [结束时间 / 至今] |

**项目背景**

大语言模型（LLM）因训练数据存在时效性限制且无法覆盖企业私有知识，直接使用时答案准确率低、易产生"幻觉"。本项目旨在构建一套生产可用的 RAG 智能体平台，将企业知识库与 LLM 结合，实现高准确率的智能问答与工具调用能力。

**技术栈**

`Java 17` · `Spring Boot 3` · `MyBatis Plus` · `MySQL` · `Milvus` · `Redis` · `RocketMQ` · `React 18` · `TypeScript` · `阿里云百炼 / SiliconFlow / Ollama`

**核心职责与实现**

- **多路召回引擎**：设计并实现 `SearchChannel` 策略接口，支持向量全局检索（Milvus 全量 ANN）与意图定向检索（按知识库分区）两路并行召回；在后处理流水线中依次执行去重、Rerank 重排与置信度过滤，多路融合有效降低了单一通道因意图识别失准导致的漏召问题

- **意图识别与引导**：基于三层意图树（领域 → 类别 → 主题）实现意图分类，结合 `IntentNodeRegistry` 和 `IntentTreeFactory` 支持动态加载；意图置信度低时自动降级到全局检索，保障零意图场景的召回覆盖率

- **查询改写**：利用 LLM 对多轮对话中的省略和代词进行语义还原，将"它怎么配置？"这类上下文依赖问题改写为自包含的完整问题，显著提升检索召回质量

- **对话记忆管理**：设计"滑动窗口 + 摘要"双层记忆方案，超出滑动窗口的历史消息由 `MemorySummarizer` 调用 LLM 异步压缩为摘要，在 Context Window 有限的前提下保持长对话的语义连贯性

- **多模型路由与熔断**：基于 CLOSED / OPEN / HALF_OPEN 三态熔断器实现模型 Failover，主模型连续失败 2 次后自动熔断并降级到备用模型，30 秒后自动探测恢复；新增模型提供商只需实现 `ChatClient` 接口并配置候选，业务层零改动

- **流式响应首包缓冲**：通过装饰器模式实现 `ProbeBufferingCallback`，在收到第一个有效 Token 前缓冲所有内容；若模型在此期间报错，静默切换备用模型重试，客户端完全无感，消除 SSE 流中途切换导致的乱码问题

- **文档摄入流水线**：采用 DAG + 节点编排模式设计摄入流水线（解析 → 分块 → 增强 → 向量化 → 写入 Milvus），每个节点独立记录执行状态，流水线配置存储于数据库支持动态调整；集成 Apache Tika 支持 PDF、Word、Markdown 等 10+ 种格式解析

- **全链路追踪**：通过自定义注解 `@RagTraceNode` + AOP 对每个 RAG 处理节点自动埋点，记录耗时、输入输出和异常；使用阿里 TTL（TransmittableThreadLocal）保证追踪 ID 在 8 个专用线程池间无损传递；前端提供瀑布图式可视化页面

- **生产级限流与幂等**：基于 Redis 信号量实现并发限流（`@ChatRateLimit`），防止 LLM 资源耗尽；提供请求提交与消息消费双维度幂等（`@IdempotentSubmit` / `@IdempotentConsume`），均通过 AOP 零侵入实现

- **MCP 工具集成**：独立部署 `mcp-server`（端口 9099）实现 MCP 协议服务端；主服务通过 `MCPClient` 获取工具列表，借助 `LLMMCPParameterExtractor` 从 LLM 输出中提取工具调用意图和参数，`RemoteMCPToolExecutor` 执行后将结果反馈给 LLM，赋予系统执行外部操作的 Agent 能力

- **前端控制台**：基于 React 18 + TypeScript + Tailwind CSS 独立开发 22+ 功能页面，包含聊天界面（SSE 流式渲染 + Markdown 高亮）、知识库管理、摄入流水线配置、意图树编辑、追踪链路可视化等

**项目成果**

- 后端代码约 40,000 行（400+ 源文件），前端代码约 18,000 行，覆盖 20 张业务数据库表
- 系统设计了 8 个专用线程池并通过 TTL 保证上下文无损传递，支撑高并发场景
- 具备体验环境只读拦截器，可安全演示而不影响生产数据
